## 1. 产品定位

**一句话**：把互联网上看到的一切收进自己的仓库，让 AI 自动整理、理解并替你检索与写作的个人知识管理系统。

**它不是什么**：

- 不是纯书签管理器（Raindrop 已做得足够好，本产品的差异化在「理解」与「产出」）；
- 不是笔记软件（Obsidian/Notion 面向写作，本产品面向**外部内容的采集与消化**）；
- 不是又一个 ChatGPT 套壳（AI 的回答必须能追溯到用户自己的收藏，见 FR-AI-06）。

**核心命题**：用户每天收藏 5–50 条内容，但 90% 再也不会打开。灵感仓解决的是**收藏后的第二公里**——让收藏在需要时能被找到、被理解、被引用、被写成东西。

### 1.1 目标用户

| 画像 | 典型行为 | 核心诉求 | 付费意愿 |
|---|---|---|---|
| 研究者 / 学生 | 论文、公众号长文、报告 PDF 大量囤积 | 按主题聚合成专题、能溯源引用 | 高（学期制） |
| 内容创作者 | 攒选题、素材、竞品案例 | 从素材库直接生成脚本/大纲 | 高（生产工具） |
| 产品 / 设计 | 竞品截图、灵感图、设计参考 | 图片语义搜索、视觉灵感墙 | 中高 |
| 工程师 | 技术文档、GitHub、博客 | 全文+语义检索、代码片段 | 中 |
| 泛知识工作者 | 微信收藏、B 站收藏夹 | 一键迁入、跨端同步 | 中 |

### 1.2 差异化（必须做进产品的三件事）

1. **中文互联网原生**：微信公众号、B 站、小红书、知乎、微博的收藏与解析，且对登录墙/防盗链有明确降级路径（FR-COL-11）。
2. **可溯源的 AI**：所有 AI 结论带 `[n]` 引用，点击回到原文段落（FR-AI-06/07）。
3. **专题与创作闭环**：收藏 → 专题 → 成稿，同一条链路内完成（FR-KB-01、FR-CR-01）。

## 3. 功能需求

优先级定义：**P0** = 首个可发布版本必须可用；**P1** = 商业化前必须；**P2** = 增强项。
每条需求给出验收标准（AC），测试用例编号见 [TEST_PLAN](TEST_PLAN.md)。

### 3.1 采集与收藏（Collection）

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-COL-01 | URL 收藏：粘贴链接即入库，后台抓取元数据 | P0 | 提交后 <2s 出现占位条目，抓取完成后标题/封面/正文就位；失败有明确状态与重试入口 |
| FR-COL-02 | 图片收藏：上传 / 拖拽 / 粘贴 / 扩展右键 | P0 | 支持 jpg/png/webp/gif/heic，单文件 ≤20MB，自动生成缩略图与 OCR 文本 |
| FR-COL-03 | PDF 收藏：上传并抽取文本与原页图 | P0 | 文本型 PDF 可全文搜索；扫描件走 OCR 队列并标注 `ocr_pending→done` |
| FR-COL-04 | 视频链接收藏：B 站/YouTube/直链 | P1 | 抓到标题、封面、时长；无法下载时保留链接与元数据，不阻塞 |
| FR-COL-05 | 文件收藏：任意类型附件 | P1 | 存储配额内可上传；非可解析类型仅存元数据+下载 |
| FR-COL-06 | 文字笔记：原生 Markdown 记录 | P0 | 支持 Markdown 编辑与预览，可直接被 AI 检索 |
| FR-COL-07 | 正文提取与阅读视图 | P0 | 提取成功率 ≥85%（样本见 TEST_PLAN §4）；提取失败降级为链接+摘要 |
| FR-COL-08 | 自动标题、封面、favicon、站点名 | P0 | 抽不到时按域名+日期兜底，不留空白卡片 |
| FR-COL-09 | 标签：手动 + AI 自动，层级与合并 | P0 | AI 标签与手动标签分色显示；合并标签不丢关联 |
| FR-COL-10 | 多级收藏夹 + 共享协作 | P1 | 支持 3 级嵌套；共享列表支持 owner/editor/viewer 三种角色 |
| FR-COL-11 | 中国内容源适配器 | P0 | 微信公众号、B 站、小红书、知乎至少各有一条成功路径与一条降级路径（见 §3.1.1） |
| FR-COL-12 | 批量管理 | P1 | 支持多选后批量打标签、移动、归档、删除，≤500 条/次 |
| FR-COL-13 | 去重 | P1 | 同 URL 归一化（去 utm/锚点/短链展开）后提示重复，可强制新增 |
| FR-COL-14 | 导入 | P0 | 支持 Karakeep 导出、浏览器书签 HTML、Raindrop CSV、Pocket HTML |
| FR-COL-15 | 导出 | P0 | 全量导出为 JSON + 原始资产，可再导入还原 |
| FR-COL-16 | 全文搜索 | P0 | 标题/正文/OCR/高亮全字段，P95 <300ms（本地实例、10 万条） |
| FR-COL-17 | 离线阅读 | P1 | 移动端可离线打开已缓存正文与图片 |

#### 3.1.1 中国内容源适配（关键约束）

| 站点 | 自动解析 | 已知限制 | 降级方案（必须实现） |
|---|---|---|---|
| 微信公众号 | 正文、作者、发布时间 | 部分文章需登录/环境验证；图片有防盗链 | 浏览器扩展「剪藏当前页」→ 传 HTML；或用户粘贴全文 → 存为笔记并保留原链接 |
| B 站 | 标题、封面、UP 主、时长、简介 | 视频本体受版权与登录限制，不做下载 | 存链接+元数据+封面；可选「字幕/简介」文本化 |
| 小红书 | 标题、正文、图片（尽力） | 强登录墙、风控 | 扩展剪藏；失败时保存链接+用户手填摘要 |
| 知乎 | 问题/回答正文 | 反爬与折叠 | 扩展剪藏；或抓取失败降级为链接 |

> 实现原则：**解析失败不算收藏失败**。任何站点都必须能退化成「链接 + 用户补充」的可检索条目。

## 4. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | Web 首屏 LCP <2.0s（本地实例）；列表滚动 60fps；搜索 P95 <300ms；AI 首 token <1.5s |

### 5.2 计费与状态机

订单状态：`created → pending → paid → fulfilled`，异常分支 `failed / refunding → refunded / canceled`。
订阅状态：`trialing / active / past_due / canceled / expired`。
权益物化：订阅状态变更时写入 `users` 的 tier 与配额列，热路径不查订阅表（沿用上游设计，见 [ARCHITECTURE](ARCHITECTURE.md) §6）。

### 5.3 商业化指标

- 试用→付费转化 ≥4%
- 月流失 ≤5%
- ARPU ≥¥35
- AI 成本占收入 ≤18%

## 6. 关键用户旅程（必须逐条走通）

1. **首次体验**：注册 → 空状态引导 → 装扩展 → 收藏 3 条 → 看到 AI 自动打标签 → 搜索命中。
2. **深度使用**：收藏 50 条 → 建收藏夹 → 用 AI 搜索问「我收藏的关于 RAG 的资料说了什么」→ 得到带引用回答 → 点引用回到原文段落。
3. **专题产出**：输入主题「向量数据库选型」→ 生成专题报告 → 导出 Markdown → 在创作工作台扩写成文章。
4. **团队协作**：建共享收藏夹 → 邀请同事（viewer）→ 同事只能看不能改 → 升级为 editor 后可加条目。
5. **付费转化**：免费额度用尽 → 明确提示 → 升级 Pro → 额度即时生效（无需重新登录）。
6. **中国内容**：把微信文章链接粘进来 → 解析失败 → 自动提示「用扩展剪藏」→ 剪藏成功并可检索。

## 7. 验收与「完成」定义（Definition of Done）

一个功能只有同时满足以下 6 条才算完成：

1. 真实后端 + 真实数据库，无 mock 数据；
2. 有 loading / empty / error / 正常四态；
3. 有自动化测试（单元或 E2E），且在本机跑绿；
4. 数据隔离用例通过（A 用户看不到 B 用户数据）；
5. 桌面（1440）/ 平板（834）/ 手机（390）三档布局无溢出、无遮挡；
6. 控制台零报错，关键交互无 >200ms 的主线程阻塞。

## 8. 不做的事（明确排除）

- 不做社交信息流、关注、点赞榜（与「私人知识库」定位冲突）；
- 不做内容平台/公开博客托管；
- 不做浏览器内的广告拦截、下载器；
- 不做视频转码与版权内容下载；
- 不在本阶段做原生 Windows/macOS 客户端（先 PWA，Tauri 另议，见 [DECISIONS](DECISIONS.md) ADR-006）。
