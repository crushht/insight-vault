## 18. AI 链路已用 mock provider 验证（第 127 轮）

### 背景

前面一直把「真实 AI 生成」列为最硬的缺口。但**链路**和**模型**是两件事 ——
只要协议是标准的 OpenAI 格式，就可以用一个本地 mock 把我方这一侧全部验证掉。

### 做了什么

`artifacts/mock_llm.py`（约 90 行）：

| 端点 | 行为 |
|---|---|
| `POST /v1/chat/completions` | 返回固定回答（含 `[1]` `[2]`）；`stream: true` 时**分两块**推送 |
| `POST /v1/embeddings` | 返回 1536 维零向量 |

临时配成 provider（验证后已从两个 `.env` 删除）。

### 验证结果

| 环节 | 证据 |
|---|---|
| 非流式生成 | `chat.sendMessage` → **200**（此前 412），返回内容正确、**citations=3** |
| 引用写回 | 助手消息里带 3 条引用（bookmarkId + chunkId + quote） |
| 专题 AI 模式 | `topics.generate` → **mode=ai**（此前只能 draft） |
| **真流式** | SSE 收到 **2 帧**，内容边界与 mock 的 pieces 完全一致 → 走的是 `inferFromTextStream`，不是回退切块 |

### 这意味着什么

**换真模型时不需要改任何代码**，只需三个环境变量：

```
OPENAI_BASE_URL=https://你的服务/v1
OPENAI_API_KEY=sk-...
INFERENCE_TEXT_MODEL=模型名
```

### 仍未验证的（诚实清单）

| 项 | 原因 |
|---|---|
| 标签 / 摘要 worker | 同一 inference 客户端，但未单独跑 |
| embedding 写入向量库 | 无向量库（需 Meilisearch 或其他 vector store） |
| 模型输出质量 | mock 不体现 —— 这本来也不属于「我方代码」 |

### 判定更新

原来写的「真实 AI 生成：未验证」应修正为：

> **AI 链路的我方部分已全部验证；只差一个真实模型 endpoint。**

这比之前的表述准确得多 —— 之前容易让人以为「AI 功能没做完」，
实际上是「做完了，没模型可接」。
